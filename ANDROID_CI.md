# MotoFix Driver Android builds

The `Android Build` workflow builds the driver app in
`interfaces/motofix-driver-app` on GitHub's Ubuntu runner. It builds the Vite
web app, generates the Capacitor Android project on the runner when needed,
syncs it, and builds the APK. Developers do not need Android Studio or a local
Android SDK. The Android project is not required to be committed.

## Production API configuration

Add these as GitHub Actions **Variables** (recommended) or **Secrets** in the
repository settings. The workflow has these production defaults, so the
endpoints are baked in even when settings are not added:

| Name | Value |
| --- | --- |
| `VITE_API_AUTH_URL` | `https://motofix-auth.onrender.com` |
| `VITE_API_MATCHING_URL` | `https://motofix-matching.onrender.com` |
| `VITE_API_REQUESTS_URL` | `https://motofix-dispatch.onrender.com` |
| `VITE_API_MECHANICS_URL` | `https://motofix-verification.onrender.com` |
| `VITE_WS_URL` | `wss://motofix-dispatch.onrender.com/ws/jobs` |
| `VITE_PROVIDER_URL` | `https://motofixug.netlify.app` |

The workflow rejects non-HTTPS API/provider URLs, a non-WSS WebSocket URL, or
localhost values. Optional `VITE_GOOGLE_MAPS_API_KEY`,
`VITE_GOOGLE_MAPS_MAP_ID`, and `VITE_FIREBASE_*` values can be added as
repository Secrets if those features are configured. MOTOBOT is explicitly
disabled in this build.

For the Netlify driver site, set the same `VITE_API_AUTH_URL`,
`VITE_API_MATCHING_URL`, `VITE_API_REQUESTS_URL`, `VITE_API_MECHANICS_URL`,
`VITE_WS_URL`, and `VITE_PROVIDER_URL` values in
**Site configuration > Environment variables**,
then trigger a new production deploy so Vite bakes them into the site. OTP
registration, login, and resend requests use the auth URL only.

After changing CORS in `services/motofix-auth-service`, push the change and
redeploy `motofix-auth-service` on Render before retrying browser OTP. For a
demo, open each Render service's `/docs` page once to wake free-tier services.
An `ERR_NAME_NOT_RESOLVED` may be caused by the device's or ISP's DNS; switching
the device DNS to `1.1.1.1` can help, but DNS failures must not prevent login UI
or GET HELP from rendering.

## Run a build

- Every push to `release/v1` builds and uploads a debug APK.
- To run manually, open the repository's **Actions** tab, select **Android
  Build**, click **Run workflow**, select branch **release/v1**, choose
  **debug** under `build_type`, then click **Run workflow**. When complete,
  open the run and download the `motofix-driver-debug-apk` artifact.
- For a signed release, first add the four signing secrets below, then follow
  the same steps but choose **release**. Download
  `motofix-driver-release-apk-aab` for both the APK and AAB.

To install the debug build on an Android phone, download and extract the
artifact ZIP, transfer `app-debug.apk` to the phone (for example, with USB),
open the APK, and allow installation from that file manager/browser if Android
prompts. Confirm the installation prompt. Debug APKs use the standard debug
key generated by the runner and need no signing secrets.

Render free-tier services may sleep; the first API calls after inactivity can
take longer while the services start.

## Optional release signing secrets

Create a repository signing key and add all four values under **Settings >
Secrets and variables > Actions > Secrets**:

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Base64-encoded keystore file |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | Key alias in the keystore |
| `ANDROID_KEY_PASSWORD` | Password for that key |

Release signing secrets are not needed for debug builds. Keep the keystore and
passwords private; losing the keystore can prevent future updates to an
application published with that signing identity.
